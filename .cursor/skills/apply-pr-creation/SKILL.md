# PR Creation

Create a pull request on the upstream repository. Called by both one-shot and phase-iterative flows.

## Inputs

- `inputs/jira.yaml` → `target_repo`, `jira_key`, `plan_phases[]`
- `state.yaml` → `current_plan_phase` (phase-iterative) or mode context
- `plan.md` → phase goal, user story mapping
- Fork owner from auto-fork setup

## PR Title Format

**Phase-iterative:** `<phase_jira_key>: [US-XX] <user story title>`
- Fallback if `plan_phases[N].jira_key` is `SKIPPED` or `PENDING`: `<jira_key>: [US-XX] <user story title>`
- Extract `US-XX` and title from `plan.md` Phase N → `User Story` field.

**One-shot:** `<jira_key>: <change summary from specs.md> (US-01, US-02, ...)`

## PR Body Template

```bash
gh pr create \
  --repo <upstream_org/repo> \
  --head <fork_owner>:<branch> \
  --base main \
  --title "<title>" \
  --body "$(cat <<'EOF'
## <title>

**Jira:** <jira_base_url>/browse/<jira_key>
**Parent:** <jira_base_url>/browse/<parent_jira_key>
**Phase:** <N> of <total_plan_phases>  (omit for one-shot)
**Change:** <change-name>

### Description
<phase goal from plan.md or high-level summary from specs.md>

### Tasks Completed
- <task_id>: <task_title> ✓
- ...

### Files Changed
- <file_path> — <brief description>
- ...

### Verification
- Build: PASS
- Tests: PASS (N/N)
- Make verify: PASS

---
*🤖 This Pull Request was generated by an internal Red Hat AI agent (OpenSpec). All outputs must be reviewed by a human prior to merging.*
EOF
)"
```

## Post-Creation

- Record PR URL in `state.yaml` → `phase_pr_urls` (phase-iterative) or as final PR URL.
- Output: "PR raised on upstream: <PR_URL>."
